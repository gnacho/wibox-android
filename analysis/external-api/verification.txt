## Alcance

Verificación estática de coherencia entre `docs/external-api.md`, `analysis/external-api/api-contract.json`, la matriz actual de providers y los límites del inventario dinámico. No verifica una implementación Android, porque esta hoja no contiene un servicio, AIDL compilado, SDK ni tests Android.

## Primera ejecución y corrección

Comando:

```bash
PYTHONDONTWRITEBYTECODE=1 python3 analysis/external-api/verify_external_api.py --repo /home/nacho/Documentos/Repos/wibox-kotlin
```

Salida real inicial, exit 1:

```text
DESIGN_ERROR local_only capability core.capability_negotiation cannot become runtime support
```

La regla del verificador era demasiado amplia para `core.capability_negotiation`, que está clasificada como infraestructura `contract_local` y no como soporte stock elevado. Se limitó la excepción a `core.lifecycle` y `core.capability_negotiation`. Después se repitió el control completo.

## Segunda pasada de amenazas y compatibilidad

Se revisó de nuevo el diseño antes de la ejecución final. Se añadieron estos requisitos:

1. Capturar UID, identidad y generación del grant durante la transacción Binder y adjuntarlos al trabajo background.
2. Denegar dispositivos cuando el grant está vacío y prohibir comodines.
3. Permitir desuscripción y cancelación de operaciones propias tras revocación, sin exponer datos.
4. Deduplicar request IDs sin volver a ejecutar acciones y devolver `CONFLICT` si cambia el payload.
5. Prohibir cambios de layout Parcelable dentro de una major y exigir tipos V2.
6. Mantener referencias fuertes a callbacks hasta completar y no retener callbacks en altas fallidas.
7. Exigir comprobación de compatibilidad binaria del SDK.

Se añadieron controles negativos para replay por request ID, pérdida de identidad background y cambio de layout Parcelable.

## Límites de esta verificación

- No se compiló AIDL ni se ejecutó lint Android.
- No se ejecutaron tests unitarios ni de instrumentación Android.
- No existen todavía las dos apps de prueba con firmas distintas.
- No se probaron UID, certificados, allowlist, callbacks, Binder death, cancelación ni rate limit en runtime.
- No se ejecutaron acciones, lecturas QVCloud, consultas de actualización ni pruebas de hardware.
- No se inspeccionaron transacciones Binder reales ni logs de una implementación inexistente.
- No se usó red, no se instalaron paquetes y no se accedió a dispositivos.
- No se editó el repo fuente, no se hicieron commits y no se publicó ningún artefacto.
- El resultado `WIBOX_EXTERNAL_API_DESIGN_VERIFIED` acredita únicamente las comprobaciones estáticas anteriores. No significa que la API esté disponible ni que su seguridad runtime esté probada.
